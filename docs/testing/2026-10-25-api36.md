# API 36 regression audit — 25 October 2026

The full device suite is **not passing**. The broad AI run completed 340 cases: 310 passed, 29 failed, and one was skipped. All 29 failed again in a separate filtered run. Many failures concern stale UI expectations or test setup; they must not be reported as 29 confirmed application defects. The real system-PIN completion check remains unresolved.

## Environment and source boundary

- Dedicated `Tally_Test_API36` Android 16 / API 36 x86_64 emulator, 1080 × 2400 pixels at 420 dpi, with Windows Hypervisor Platform acceleration and software graphics.
- The emulator was stopped and restarted before the device suites. No data wipe was performed.
- Synthetic fixtures and isolated application IDs: `com.smartexpense.safety` for the broad AI run; `com.smartexpense.reference` for the finalized-source checks. The ordinary `com.smartexpense` installation was not used for these instrumented suites.
- The initial source snapshot was taken from `fc32a6584a90c559d203fc63166fe7d08eacfbbf` plus the then-current, unfinished Unicode parser changes. It was copied into an ignored local directory so concurrent edits could not change an active run.
- After the broad run, the four changed parser/test files were replaced with their finalized versions from commit `020e983` (`Support Unicode amounts and strengthen command draft review`). Subsequent checks use that source boundary. Later working-tree changes are outside this report.
- Debug builds, not production release builds. This audit does not change the verification claims for the previously published APKs.

All 24 `EditorialAdaptiveTest` combinations passed: widths 320, 360, 393, 412, 440, and 600 dp, each at text scales 1.0, 1.3, 1.5, and 2.0. These cases check the five screens covered by that test, not every screen in the app. Separate secondary-layout audit cases also passed.

Two captured synthetic screens were visually inspected: the normal calendar and accounts at 320 dp / 200% text. Visible amounts fitted without horizontal clipping. Other screenshot-generation passes establish rendering/capture success, not a complete visual review.

## Reproduction

Use a disposable emulator and the checked-in [data-safety init script](../../tools/data-safety-build.init.gradle) to isolate the application identity. Select the intended emulator serial before connected checks; no real financial data is needed.

```powershell
$env:ANDROID_SERIAL = 'emulator-5580'
.\gradlew.bat -I tools/data-safety-build.init.gradle -PtallyAi=true :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug --continue --no-daemon --console=plain --max-workers=2
.\gradlew.bat -I tools/data-safety-build.init.gradle -PtallyAi=true :app:connectedDebugAndroidTest --no-daemon --console=plain --max-workers=2
```

The local audit ran the installed test APK directly with `adb shell am instrument -w -r -e timeout_msec 90000 PACKAGE.test/androidx.test.runner.AndroidJUnitRunner`, using `.safety` or `.reference` as described above. Android instrumentation can return a successful shell exit status while reporting test failures: inspect the final `Tests run` / `FAILURES!!!` output and individual status records, not just the process exit code.

The finalized non-AI critical selection covered these classes: `InstallationDataSafetyTest`, `BackupTest`, `BillScannerTest`, `CalendarBackupPreferenceTest`, `DistributionVariantTest`, `LocalCommandDraftFlowTest`, `ChatHistoryImportFlowTest`, `ChatHistoryRepositoryTest`, `SharedRefundRepositoryTest`, `ReminderEfficiencyTest`, `ReportQueryTest`, `RepositoryTest`, `CorrectionRepositoryTest`, `ReceiptRepositoryTest`, `PersonalWalletRepositoryTest`, `CalculatorScreenTest`, `EditorialAdaptiveTest`, `AppLockActivityTest`, `AppLockUiTest`, and `AppLockSystemAuthTest`.

The finalized AI targeted selection covered `LocalCommandModelTest`, `ExtendedCommandRuntimeTest`, `LocalCommandDraftFlowTest`, `DistributionVariantTest`, `ChatHistoryImportFlowTest`, `ChatHistoryImportUiTest`, and `CalculatorScreenTest`. These checks verified the bundled model assets, model execution, reviewed drafts/imports, and calculator interactions. They do not replace a full finalized-source AI device rerun.

Raw logs, XML results, source hashes, APKs, emulator storage, and synthetic screenshots remain in the ignored local `.build-cache/thorough-tests/` and `.build-cache/test-phone/` directories. They are not source assets or release downloads.
